UBUNTU 22.04 SERVER · VIRTUALBOX · PUTTY · FILEZILLA

Ubuntu 22.04 Server + VirtualBox 설치 따라하기

Windows 11 PC에서 KAIST Ubuntu 미러를 이용하여 Ubuntu 22.04.5 Server ISO를 다운로드하고,
Oracle VirtualBox에 가상 머신을 만든 뒤 Ubuntu Server를 설치하는 전체 과정입니다.

Windows 11 호스트VirtualBox 7.2.xUbuntu Server 22.04.5 LTSPuTTY + PuTTYgenFileZilla SFTPNAT 2222 → 22

00이번 실습에서 만들 환경

항목 설정
호스트 PC Windows 11 64비트
가상화 프로그램 Oracle VirtualBox 7.2.x
SSH 클라이언트 PuTTY + PuTTYgen
게스트 OS Ubuntu Server 22.04.5 LTS 64비트
CPU 2개 권장
메모리 4GB 권장
가상 디스크 30GB 권장
네트워크 NAT
Ubuntu ISO ubuntu-22.04.5-live-server-amd64.iso
ⓘ

최소 권장 사항

  • PC 메모리: 8GB 이상
  • 여유 디스크: 40GB 이상
  • BIOS/UEFI에서 Intel VT-x 또는 AMD-V 가상화 기능 활성화
  • 인터넷 연결
  • PuTTY / PuTTYgen (Windows에서 SSH 접속 및 키 생성)

01Ubuntu 22.04 Server ISO 다운로드

1-1KAIST Ubuntu 미러 접속

웹 브라우저에서 아래 주소로 접속합니다.

https://ftp.kaist.ac.kr/ubuntu-cd/22.04/

접속하면 여러 파일이 보입니다.

그중 Server 버전은 다음 파일입니다.

화면 · 입력값ubuntu-22.04.5-live-server-amd64.iso
⚠

desktop이 들어간 파일이 아니라 반드시
live-server-amd64.iso 파일을 선택합니다.

1-2다운로드할 파일 찾기

목록에서 다음 파일을 찾습니다.

화면 · 입력값ubuntu-22.04.5-live-server-amd64.iso

파일 크기는 약 2GB입니다.

직접 다운로드 주소:

https://ftp.kaist.ac.kr/ubuntu-cd/22.04/ubuntu-22.04.5-live-server-amd64.iso

파일 이름을 클릭하여 다운로드합니다.

예를 들어 Windows의 다운로드 폴더에 저장했다면:

화면 · 입력값C:\Users\사용자이름\Downloads\ubuntu-22.04.5-live-server-amd64.iso

1-3다운로드 확인

파일 탐색기를 열고 다음을 확인합니다.

화면 · 입력값다운로드
 └─ ubuntu-22.04.5-live-server-amd64.iso

확장자가 반드시 다음과 같아야 합니다.

화면 · 입력값.iso
ⓘ

Windows가 확장자를 숨기고 있다면
파일 탐색기 → 보기 → 표시 → 파일 확장명을 체크하면 확인하기 쉽습니다.

02VirtualBox 다운로드

2-1공식 다운로드 사이트 접속

VirtualBox 공식 다운로드 페이지:

https://www.virtualbox.org/wiki/Downloads

Oracle 공식 파일 저장소:

https://download.virtualbox.org/virtualbox/

이 문서를 작성한 시점의 안정 버전은 VirtualBox 7.2.16입니다.

Windows 11 PC에서는 다음 종류의 설치 파일을 사용합니다.

화면 · 입력값VirtualBox-7.2.16-174877-Win.exe

직접 다운로드:

https://download.virtualbox.org/virtualbox/7.2.16/VirtualBox-7.2.16-174877-Win.exe

ⓘ

버전은 이후 업데이트될 수 있습니다.
공식 Downloads 페이지에 더 최신 안정 버전이 있다면 그 버전을 사용해도 됩니다.

다운로드한 파일을 실행합니다.

화면 · 입력값VirtualBox-7.2.16-174877-Win.exe

화면 · 입력값Network Interfaces

예를 선택합니다.

5-1새 가상 머신 생성

화면 · 입력값New

또는

화면 · 입력값Machine → New

5-2가상 머신 이름 입력

다음과 같이 설정합니다.

Name

기본값을 사용해도 됩니다.

화면 · 입력값C:\Users\사용자이름\VirtualBox VMs

화면 · 입력값ubuntu-22.04.5-live-server-amd64.iso

화면 · 입력값☑ Skip Unattended Installation

설치 과정을 직접 보는 편이 이해하기 쉽습니다.

06CPU와 메모리 설정

6-1메모리

권장:

화면 · 입력값4096 MB

즉 약 4GB입니다.

PC 메모리가 부족하면:

화면 · 입력값2048 MB

로 설정해도 Ubuntu Server 기본 실습은 가능합니다.

6-2CPU

권장:

화면 · 입력값2 CPUs

PC 사양이 충분하다면 4개를 할당해도 됩니다.

일반적인 권장 설정

화면 · 입력값Memory : 4096 MB
CPU    : 2
ⓘ

호스트 PC의 CPU와 메모리를 너무 많이 가상 머신에 할당하면
Windows가 느려질 수 있습니다.

Next를 클릭합니다.

07가상 하드디스크 만들기

7-1디스크 크기

다음과 같이 설정합니다.

화면 · 입력값30 GB

Ubuntu Server 기본 실습에는 충분합니다.

개발 도구를 많이 설치할 계획이라면:

화면 · 입력값50 ~ 100 GB

를 사용할 수 있습니다.

7-2디스크 생성

VirtualBox 버전에 따라 새 가상 디스크 생성 옵션이 표시됩니다.

기본값을 사용합니다.

권장 구성:

화면 · 입력값VDI
Dynamically allocated
30 GB

동적 할당 방식은 실제로 사용한 만큼만 Windows 디스크 공간을 차지합니다.

문제 1. PuTTY에서 Connection refused가 나온다

$ 명령chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
chown -R $USER:$USER ~/.ssh

공개키가 한 줄로 정확히 들어갔는지 확인합니다.

$ 명령cat ~/.ssh/authorized_keys

PuTTY에 지정한 .ppk 파일이

63FileZilla 자주 발생하는 오류

문제 1. Connection refused

예:

화면 · 입력값ECONNREFUSED
Connection refused

먼저 Ubuntu VM이 실행 중인지 확인합니다.

Ubuntu에서:

$ 명령sudo systemctl status ssh

SSH 서비스가 실행되지 않았다면:

$ 명령sudo systemctl enable --now ssh

VirtualBox 포트포워딩도 확인합니다.

화면 · 입력값Host IP    : 127.0.0.1
Host Port  : 2222
Guest Port : 22

문제 2. Connection timed out

VirtualBox VM이 실행 중인지 확인합니다.

그리고 FileZilla 설정이 다음과 같은지 확인합니다.

화면 · 입력값Host : 127.0.0.1
Port : 2222

이 실습에서는 Ubuntu VM의:

화면 · 입력값10.0.2.15

주소를 FileZilla Host에 직접 넣는 방식이 아니라
VirtualBox NAT 포트포워딩을 사용합니다.

문제 3. Authentication failed

예:

화면 · 입력값Authentication failed

다음을 확인합니다.

화면 · 입력값Protocol   : SFTP
Logon Type : Key file
User       : ubuntu

그리고 Key file이 PuTTY에서 사용한 것과 같은 파일인지 확인합니다.

화면 · 입력값ubuntu-virtualbox.ppk

Ubuntu에 공개키가 등록되어 있는지도 확인합니다.

$ 명령cat ~/.ssh/authorized_keys

권한 확인:

$ 명령chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

문제 4. 일반 FTP로 접속해서 실패한다

FileZilla에서 프로토콜을 반드시 다음과 같이 선택해야 합니다.

화면 · 입력값SFTP - SSH File Transfer Protocol

일반 FTP의 기본 포트는 21번이지만
이번 실습에서는 FTP 서버를 설치한 것이 아닙니다.

사용하는 것은 SSH 기반 SFTP입니다.

화면 · 입력값FileZilla
    ↓
SFTP
    ↓
Windows 2222
    ↓
VirtualBox NAT
    ↓
Ubuntu SSH 22

문제 5. Permission denied로 업로드가 안 된다

일반 사용자는 시스템 디렉터리에 바로 파일을 올리지 못할 수 있습니다.

예:

화면 · 입력값/etc
/usr
/var

초보 실습에서는 자신의 홈 디렉터리를 사용합니다.

화면 · 입력값/home/ubuntu

또는:

화면 · 입력값~

예:

화면 · 입력값/home/ubuntu/upload

필요하면 PuTTY에서 업로드용 폴더를 만듭니다.

$ 명령mkdir -p ~/upload

FileZilla에서:

화면 · 입력값/home/ubuntu/upload

로 파일을 전송합니다.

시스템 디렉터리로 옮겨야 한다면 업로드 후 PuTTY에서 sudo를 사용합니다.

예:

$ 명령sudo mv ~/upload/test.conf /etc/example/

문제 6. 비밀키 파일이 선택되지 않는다

FileZilla Site Manager에서:

화면 · 입력값Protocol   : SFTP
Logon Type : Key file

을 먼저 선택한 뒤 비밀키를 지정합니다.

앞 단계에서 PuTTYgen으로 만든:

화면 · 입력값ubuntu-virtualbox.ppk

파일을 사용합니다.

문제 7. 비밀키 passphrase를 계속 묻는다

PuTTYgen에서 키를 생성할 때 passphrase를 설정했다면
FileZilla가 키를 사용할 때 passphrase를 물을 수 있습니다.

이것은 정상적인 보안 동작입니다.

개인 PC의 교육용 VirtualBox에서 입력 없는 접속이 목적이라면
passphrase 없는 실습 전용 키를 사용할 수 있습니다.

실제 외부 서버에서는 passphrase가 있는 키를 사용하는 것을 권장합니다.

이제 Windows 11 안의 VirtualBox에서 Ubuntu Server 22.04.5 LTS를 실행할 수 있으며,
PuTTY에서는 공개키/비밀키 인증으로 사용자명과 비밀번호를 매번 입력하지 않고 SSH 접속할 수 있고,
