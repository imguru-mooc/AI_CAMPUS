Interval Tree 해부 — 삽입·삭제·검색, 그리고 천장(maxHi)

보통의 BST는 「같은 값」을 찾지만, 구간의 겹침은 왼쪽·오른쪽 어디에나 있을 수 있어 그대로는 못 찾습니다. 해법은 증강 — RB 트리(정렬 key = 구간의 시작)의 각 노드에 maxHi(내 서브트리에서 가장 멀리 뻗은 끝) 하나를 더 얹는 것. 삽입·삭제 때 이 「천장」이 어떻게 유지되고, 검색 때 어떻게 서브트리를 통째로 버리게 해 주는지 봅니다.

Interval Tree — 노드 = [시작,끝) + ≤maxHi(천장) · 초록 = 방문/발견 · 보라 번쩍 = maxHi 갱신 · 흐림 = 가지치기
대기 중 — 삽입·삭제·검색이 여기에 기록됩니다
key = 시작
정렬은 구간의 시작만 본다 — 삽입·삭제는 그냥 RB 트리 그대로.
증강 = maxHi
각 노드가 「내 서브트리의 최대 끝」을 기억 — 값 하나가 겹침 검색을 가능케 한다.
유지 비용 = 경로만
삽입·삭제·회전 때 바뀌는 maxHi는 지나간 경로의 O(log n)개뿐.
검색 = 가지치기
왼쪽 천장 ≤ 질의 시작 → 왼쪽 전체에 겹칠 구간이 없다 — 통째로 건너뛴다.
예측 질문 — 겹침은 왼쪽·오른쪽 어느 자식에나 있을 수 있는데, 무엇을 알고 있으면 한쪽을 통째로 버릴 수 있을까요?
