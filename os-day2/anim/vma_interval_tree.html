Interval Tree 에뮬레이터 — 구간으로 다스리는 주소 공간

프로세스의 가상 주소 공간은 VMA(구간)들의 집합입니다 — code, heap, stack, mmap…. 커널은 이 구간들을 시작 주소를 key로, 서브트리 최대 끝(maxHi)을 증강값으로 단 RB 트리(interval tree)에 담아 「이 주소는 누구 땅인가(find_vma)」와 「이 구간, 겹치나」를 가지치기 O(log n)으로 답합니다. x86 페이징 편의 Page Fault가 던진 첫 질문의 자료구조가 바로 이것입니다.

가상 주소 공간 0 ~ 256K — 색 = VMA · 어두움 = 빈 틈 · 주황 점선 = 틈 검사 중 · 초록 실선 = 결과

Interval Tree — 노드 = [시작,끝) · 아래 작은 ≤maxHi = 이 서브트리에서 가장 멀리 뻗은 끝 · 초록 = 방문/발견 · 흐림 = 가지치기로 건너뛴 서브트리
대기 중 — 삽입·탐색·가지치기가 여기에 기록됩니다
VMA = 구간
주소 공간 관리 = 구간들의 삽입·삭제·질의 — 문제 자체가 interval 문제입니다.
key=시작 · 증강=maxHi
RB 트리에 값 하나(서브트리 최대 끝)를 더 얹으면 겹침 질의가 가능해집니다.
가지치기 탐색
왼쪽의 maxHi가 질의 시작보다 작으면 — 왼쪽 전체를 안 보고 건너뜁니다.
할당 = 틈 · 해제 = 제거
mmap은 빈 틈을 찾아 구간을 심고, munmap은 노드를 뽑아 틈을 되살립니다.
예측 질문 — VMA가 1,000개인 프로세스에서, 주소 하나가 유효한지(find_vma) 확인하는 데 비교 몇 번이면 될까요?
