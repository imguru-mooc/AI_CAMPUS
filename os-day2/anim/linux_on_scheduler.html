OS · CPU 스케줄링 · 심화 · Linux 2.4 (초창기)

O(n) 스케줄러 해부 — 전부 훑고, 제일 좋은 놈을 고른다

초창기 Linux의 방식은 우직합니다 — runqueue 하나에 모든 task를 세워 두고, schedule()이 불릴 때마다 전원을 한 명씩 훑으며 goodness(= counter + priority) 점수를 매겨 최고점에게 CPU를 줍니다. 전원이 timeslice를 다 쓰면 epoch 재충전: counter = counter/2 + priority — 잠든 task는 남은 절반을 보너스로 챙깁니다.

모든 runnable task가 한 줄에 — 단순하지만, 고를 때마다 전원을 봐야 합니다.
goodness 전수 계산
schedule()마다 task 수만큼 비교 — 그래서 이름이 O(n).
epoch 재충전
전원 소진 시 counter = counter/2 + priority — 이때도 전체(잠든 것 포함)를 순회.
잠꾸러기 보너스
잠들어 counter를 아낀 task는 절반을 이월 — 키보드를 기다리던 대화형이 깨자마자 이깁니다.
