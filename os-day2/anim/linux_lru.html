OS · Memory 회수 · 심화 · Linux Page Reclaim

Linux LRU 해부 — 누구를 내쫓을 것인가

RAM이 가득 차면 OS는 페이지를 골라 내쫓아야 합니다. 교과서의 답은 「가장 오래 안 쓴 것(LRU)」 — 그러나 매 메모리 접근마다 목록을 갱신하는 진짜 LRU는 비용 때문에 불가능합니다. 리눅스의 타협: MMU가 공짜로 켜 주는 R(참조)비트 + active/inactive 두 줄 + 꼬리부터 훑으며 기회를 한 번 더 주는(second chance) kswapd. 잘못 쫓으면 그 대가는 refault — x86 페이징 편의 Page Fault로 되돌아옵니다.

자유 모드 — 페이지 칩 클릭 = 접근(R=1)

대기 중 — 접근·스캔·축출이 여기에 기록됩니다
진짜 LRU는 불가능
접근은 초당 수십억 번 — 그때마다 목록을 고치면 컴퓨터가 목록 관리만 하게 됩니다.
R비트 = 공짜 힌트
MMU가 접근 순간 하드웨어로 켜 주는 1비트 — OS는 가끔 읽고 지우기만 합니다.
두 줄 근사
한 번 본 것은 inactive, 거듭 보는 것은 active — 정확한 순서 대신 「뜨겁다/식었다」 2단계.
Second Chance
꼬리에서 R=1을 만나면 지우고 살려 준다 — R=0인 채 꼬리까지 밀려야 진짜 축출.
예측 질문 — 진짜 LRU를 하려면 모든 메모리 접근마다 목록을 갱신해야 합니다. 이 비용을 피하면서 「최근에 썼는가」를 아는 방법이 있을까요?
