Day 2 워크시트 — 프로세스와 자원의 하루

오늘의 도착점: Terminal에 명령 한 줄(ls ⏎)을 치는 순간 OS 안에서 벌어지는 전 과정 — fork → execve → 스케줄러 → 주소 변환 → wait — 를 빈칸 없이 이어 말할 수 있다. 각 세션의 도구(애니메이션)를 열어 확인하며 답을 적습니다.

[안내] 이 워크시트와 도구 HTML 파일들은 같은 폴더에 두세요 (도구 ▶ 버튼이 상대 경로로 열립니다). 답은 자동 저장됩니다(이 브라우저 안에서만). [강사 확정] 세션 구성은 도구 기반 제안이며, Day 2 시간별 섹션 확정 시 조정될 수 있습니다.

S1프로세스의 일생 — 태어나고, 잠들고, 사라지기까지

도착점: ps 화면의 상태 글자(R·S·Z)를 읽고, 좀비가 왜 「표의 한 줄」인지 설명한다.
도구 ▶ 프로세스 생명주기
1-1지금 이 컴퓨터에서 도는 수백 개의 프로세스 — 대부분은 어떤 상태일까? (상태 글자 하나)
1-2자식이 exit()했는데 부모가 wait()를 안 부르면, 자식은 어떤 상태로 남는가?
1-3프로세스 표의 맨 윗줄, 모든 프로세스의 시조(PID 1)의 이름은?
확인 문구 — 강사가 이렇게 말하면 진행합니다 「S1 확인 — 좀비가 왜 Memory가 아니라 표의 한 줄로만 남는지, 옆 사람에게 30초로 설명을 마친 조는 손 들어 주세요.」

S2fork() — 프로세스 복사기

도착점: fork()가 CPU(레지스터)와 Memory(주소 공간)를 어떻게 복제하고, 반환값 한 칸이 어떻게 길을 가르는지 설명한다.
도구 ▶ fork() 해부 (CPU·Memory)
2-1fork()를 한 번 호출하면 return은 몇 번 일어나는가? (숫자)
2-2자식 프로세스에서 fork()의 반환값은? (숫자)
2-3fork 후 자식이 x=99로 바꿨다. x=10이었던 부모의 x는 지금 몇인가?
2-4[심화] 실제 Linux가 fork 순간 Memory를 통째로 복사하지 않고 쓰는 순간에만 복사하는 기법의 이름은?
확인 문구 「S2 확인 — 화면의 부모·자식 패널에서 단 하나 다른 레지스터가 무엇이었는지, 조별로 한 단어로 외쳐 주세요.」

S3execve()와 wait() — 변신, 그리고 회수

도착점: Shell의 3박자 fork → execve → wait를 완성하고, 「성공한 execve는 돌아오지 않는다」를 이유와 함께 말한다.
도구 ▶ execve() 해부 ▶ wait() 해부
3-1성공한 execve() 다음 줄의 print는 실행될까? (된다/안 된다 + 이유 한 조각)
3-2execve로 Memory가 통째로 교체되어도 바뀌지 않고 유지되는 번호는?
3-3Terminal에 ls ⏎ — bash가 명령을 처리하는 3박자를 순서대로 쓰시오.
3-4wait()가 좀비의 「표 한 줄」에서 회수해 부모의 변수로 옮기는 것은? (자식이 남긴 숫자의 이름)
3-5부모가 wait 없이 먼저 죽으면, 남은 자식을 입양해 대신 거두는 프로세스는?
확인 문구 「S3 확인 — 방금 쓴 3박자를 손가락 세 개로 꼽으며 10초 안에 말해 보세요. 셋 다 나온 조는 손!」

S4CPU 나누기 ① — O(n)에서 O(1)로

도착점: 「전부 훑기」의 비용을 숫자로 말하고, 비트맵과 배열 교체가 그 비용을 상수로 만든 원리를 설명한다.
도구 ▶ O(n) 스케줄러 ▶ O(1) 스케줄러
4-1task가 1,000개일 때, O(n) 스케줄러가 다음 주인공을 한 번 고르는 데 필요한 비교는 몇 회?
4-2O(n)의 점수 공식 goodness는 무엇 + 무엇인가?
4-3O(1)이 최고 우선순위 줄을 훑지 않고 찾을 때 쓰는 자료구조/연산은?
4-4active 배열이 완전히 비면 O(1)은 무엇을 「한 번」 하고 새 epoch을 시작하는가?
4-5task가 1,000개여도 O(1)의 선택 연산 수는? (숫자)
확인 문구 「S4 확인 — 자유 모드에서 task를 8개 이상 추가한 뒤, 두 도구의 비교/연산 카운터 차이를 캡처해 두세요. S8에서 씁니다.」

S5CPU 나누기 ② — CFS, 공평의 시계

도착점: 「가장 적게 받은 사람이 다음 주자」 규칙 하나로 차례·우선순위·반응성이 전부 따라 나오는 구조를 설명한다.
도구 (RB 트리는 심화·선택) ▶ CFS 스케줄러 ▷ 심화: 레드블랙 트리
5-1CFS에서 다음에 CPU를 받는 task는 vruntime이 어떤 task인가?
5-2nice −5(높은 우선순위)의 vruntime 시계는 어떻게 가는가?
5-3오래 잠들었다 깨어난 task의 vruntime을 CFS는 어느 값 근처로 보정하는가?
5-4[심화] RB 트리 규칙 — 빨간 노드의 자식이 될 수 없는 색은?
5-5[심화] 정렬된 값을 순서대로 꽂아도 트리가 안 기울게 하는 두 가지 도구는? (둘 다)
확인 문구 「S5 확인 — 자유 모드에서 nice −5 task를 넣고 「받은 실시간」이 2배가 되는 화면을 만든 조는 손 들어 주세요.」

S6Memory 나누기 — buddy 도매상과 slab 소매점

도착점: 쪼개서 주고(split) 짝 맞춰 합치는(merge) buddy와, 페이지를 재단해 파는 slab의 2층 협업을 설명한다.
도구 ▶ buddy 해부 ▶ buddy 운용 (할당·해지) ▶ slab allocator
6-1프로그램이 20K를 요청하면 buddy는 몇 K를 내어주는가?
6-2buddy(쌍둥이)의 주소를 계산 한 번으로 찾는 공식은? 내 주소 ( ? ) 내 크기 — 괄호의 연산은?
6-3해제된 블록이 buddy와 병합되기 위한 조건은? (buddy가 어떤 상태여야 하나)
6-4slab이 buddy에게 임대해 오는 단위는?
6-5slab의 새 할당이 가장 먼저 찾아가는 진열대의 이름은? (partial / full / empty 중)
확인 문구 「S6 확인 — buddy 운용 자유 모드에서 128K 통짜 복구(병합 3연쇄)를 만든 조는 화면을 들어 보여 주세요.」

S7가상 메모리 — 지도, 문지기, 그리고 내쫓기

도착점: 주소가 값이 아니라 경로임을 분해식으로 보이고, 유효하지 않은 주소·모자란 RAM에 OS가 각각 어떻게 답하는지 말한다.
도구 (4단·interval tree는 심화·선택) ▶ x86 2단 (PGD·PTE) ▶ 주소 변환 · TLB · #PF ▶ VMA 에뮬레이터 ▶ LRU 페이지 회수 ▷ 심화: interval tree 연산
7-132비트 x86 2단에서 가상 주소는 몇+몇+몇 비트로 쪼개지는가?
7-2PGD 표 한 장은 몇 칸인가? (힌트: 4KB ÷ 4B)
7-3프로세스 A와 B가 똑같은 가상 주소를 읽으면 물리 칸은? (같다/다르다 + 무엇이 달라서인지)
7-4find_vma가 트리를 끝까지 내려가도 겹치는 VMA가 없을 때 프로세스가 받는 신호는?
7-5메모리 압박 때 inactive 꼬리의 R=1 페이지는 어떻게 되는가? (축출된다/살아남는다 + 처리)
7-6[심화] 주소 공간에 표를 겹겹이(다단) 쌓는 이유를 한 단어로 — 주소 공간의 어떤 성질 때문인가?
확인 문구 「S7 확인 — VMA 에뮬레이터에서 find_vma 미발견 → SIGSEGV 화면을 만든 조는 손! 그 주소가 왜 '남의 땅도 아닌 빈 땅'인지 한 문장으로.」

S8종합 — 명령 한 줄의 여행 (오늘의 도착점)

Terminal에 ls ⏎ — 그 순간부터 Prompt가 돌아오기까지, 오늘 배운 전부가 한 번씩 등장합니다. 여섯 빈칸을 채우고, 짝에게 1분 설명으로 마무리합니다.
8-1① bash가 자신을 복제한다 — 이 system call은?
8-2② 자식이 ls 프로그램으로 변신한다 — 이 system call은?
8-3③ 준비된 자식에게 CPU 차례를 주는 OS의 장치는? (현재 리눅스 기본 이름이면 더 좋음)
8-4④ ls가 읽는 가상 주소를 표를 걸어 물리 주소로 바꾸는 하드웨어는?
8-5⑤ 아직 안 올라온 페이지에 처음 접근하는 순간 발생하는 사건은? — 그리고 이때 frame을 내어주는 할당기는?
8-6⑥ ls가 exit(0)한 뒤, bash가 좀비를 거두고 Prompt로 돌아오게 하는 호출은?

확인 문구 — 오늘의 마무리 「S8 확인 — 하단의 채점하기를 누르면 완료 화면이 열립니다. 점수 화면을 캡처해 [강사 확정: 제출 채널]로 보내 주세요.」
