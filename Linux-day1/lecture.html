[WARN]이 나온 항목은 손을 들어 보조강사에게 알린다. 특히 vCPU 1개와 sudo 권한 없음은 Day 2 이전에 반드시 해결해야 한다. vCPU는 VM을 끄고(sudo poweroff) Settings → System → Processor에서 2로 바꾼다.

src/check_env.sh

#!/bin/bash
# check_env.sh — Linux & Shell Day 1 실습 환경 점검
# 대상: 운영체제 활용 과목에서 설치한 VirtualBox VM (Ubuntu Server 22.04.5)
# 사용법: bash check_env.sh

ok()   { printf "  [ OK ] %s\n" "$*"; }
warn() { printf "  [WARN] %s\n" "$*"; }

echo "== 1. 운영체제와 커널 =="
. /etc/os-release
if [[ "$VERSION_ID" == "22.04" ]]; then ok "배포판 : $PRETTY_NAME"
else warn "배포판 : $PRETTY_NAME (수업 기준은 Ubuntu 22.04)"; fi
KREL=$(uname -r)
if [[ "$KREL" == 5.15.* ]]; then ok "커널   : $KREL ($(uname -m)) — 스케줄러 CFS"
else warn "커널   : $KREL — HWE 커널이면 스케줄러가 EEVDF (Day 2 해석이 달라짐, 강사에게 알리기)"; fi

echo "== 2. VM 자원 =="
CORES=$(nproc)
if [ "$CORES" -ge 2 ]; then ok "vCPU   : $CORES"
else warn "vCPU   : $CORES — VM 종료 후 Settings → System → Processor 에서 2개로"; fi
MEM_MB=$(( $(grep MemTotal /proc/meminfo | awk '{print $2}') / 1024 ))
if [ "$MEM_MB" -ge 3500 ]; then ok "메모리 : ${MEM_MB} MB"
else warn "메모리 : ${MEM_MB} MB — 4096 MB 권장 (Settings → System → Base Memory)"; fi
FREE_GB=$(df -BG --output=avail / | tail -1 | tr -dc '0-9')
if [ "$FREE_GB" -ge 5 ]; then ok "디스크 여유 : ${FREE_GB} GB"
else warn "디스크 여유 : ${FREE_GB} GB — 5GB 이상 필요 (Day 4 500MB 파일 실습)"; fi
VIRT=$(systemd-detect-virt 2>/dev/null || echo none)
ok "가상화 : $VIRT"
if [ -d /sys/firmware/efi ]; then
    SB=$(mokutil --sb-state 2>/dev/null | head -1)
    if [[ "$SB" == *enabled* ]]; then warn "Secure Boot 켜짐 — Day 4 커널 모듈 로드가 거부됨"; else ok "EFI 부팅, Secure Boot 꺼짐"; fi
else
    ok "BIOS 부팅 (VirtualBox 기본) — Secure Boot 해당 없음"
fi

echo "== 3. sudo 권한 =="
if sudo -n true 2>/dev/null; then ok "sudo 사용 가능(비밀번호 캐시됨)"
elif id -nG | grep -qw sudo; then ok "sudo 그룹 소속"
else warn "sudo 권한 없음 — 강사에게 알려주세요"; fi

echo "== 4. 필수 도구 =="
for t in gcc make gdb strace valgrind perf stress-ng; do
    if command -v "$t" >/dev/null 2>&1; then ok "$t"; else warn "$t 없음"; fi
done
if [ -d "/lib/modules/$KREL/build" ]; then ok "linux-headers-$KREL"
else warn "linux-headers-$KREL 없음 (Day 4 커널 모듈 빌드에 필요)"; fi
echo
echo "설치 명령: sudo apt install -y build-essential gdb strace valgrind stress-ng linux-tools-\$(uname -r) linux-headers-\$(uname -r)"

2-3. 권한

ls -l run.sh
# -rw-r--r-- 1 ubuntu ubuntu 512 Oct  2 09:10 run.sh
chmod +x run.sh
ls -l run.sh
# -rwxr-xr-x 1 ubuntu ubuntu 512 Oct  2 09:10 run.sh
./run.sh                 # 이제 실행 가능

rwx 세 묶음은 차례대로 소유자 · 그룹 · 그 외의 권한이다. 실행 권한이 없으면 ./run.sh는 Permission denied가 난다.

2-4. 리다이렉션과 파이프

기호 의미 예

>> 출력을 파일 끝에 추가 date >> log.txt

2>&1 에러를 표준 출력과 같은 곳으로 make > build.log 2>&1
| 앞 명령의 출력을 뒤 명령의 입력으로 ps aux | grep bash

2-5. nano로 파일 고치기

GUI가 없으므로 소스 수정은 nano로 한다.

키 동작
nano 파일명 열기 (없으면 새로 만듦)
Ctrl+O → Enter 저장
Ctrl+X 종료
Ctrl+W 찾기
Alt+N 줄 번호 표시 켜기·끄기

PuTTY에서 복사는 드래그만 하면 되고, 붙여넣기는 마우스 오른쪽 클릭이다. Ctrl+C는 복사가 아니라 실행 중인 프로그램을 멈추는 키다.

2-6. 백그라운드 실행

sleep 30 &      # 끝에 & → 백그라운드에서 실행, 프롬프트 즉시 복귀
jobs            # 내 백그라운드 작업 목록
echo $!         # 방금 백그라운드로 띄운 프로세스의 PID
kill %1         # 1번 작업 종료

✏️ 빈칸 채우기 2-1

주석에 적힌 동작이 되도록 빈칸을 채우세요.

grep processor /proc/cpuinfo  wc -l    # 코어 수 세기
make > build.log                    # 출력과 에러를 모두 파일로
chmod  run.sh                       # 실행 권한 주기
sleep 30                               # 백그라운드로 실행
echo                                  # 방금 띄운 프로세스의 PID
🔒 정답 보기 2-1 
grep processor /proc/cpuinfo | wc -l    # 코어 수 세기
make > build.log 2>&1                   # 출력과 에러를 모두 파일로
chmod +x run.sh                       # 실행 권한 주기
sleep 30 &                              # 백그라운드로 실행
echo $!                                 # 방금 띄운 프로세스의 PID

| 는 앞 명령의 표준 출력을 뒤 명령의 표준 입력으로 잇습니다. 2>&1 은 "fd 2 를 fd 1 이 지금 가리키는 곳으로" 라는 뜻이라 반드시 > build.log 뒤에 써야 둘 다 파일로 갑니다(🎬 D1-2 의 순서 함정). chmod +x 는 실행 권한을 더하고, 끝의 & 는 셸이 기다리지 않게 하며, $! 는 그렇게 띄운 마지막 백그라운드 PID 입니다.

✏️ 괄호 넣기 2-2

  1. 실행 권한을 추가하는 명령은 chmod run.sh 이다.
  2. 표준 출력과 에러 출력을 모두 log.txt로 보내려면 make > log.txt 라고 쓴다.
  3. 앞 명령의 출력을 뒤 명령의 입력으로 연결하는 기호는 이다.
  4. 방금 백그라운드로 실행한 프로세스의 PID가 저장된 변수는 이다.
  5. nano에서 저장하는 키는 Ctrl+ 이다.
🔒 정답 보기 2-2
  1. +x
  2. 2>&1
  3. |
  4. $!
  5. O

+x 는 소유자·그룹·기타 모두에게 실행 권한을 더합니다(u+x 는 소유자만, 755 는 rwxr-xr-x 로 통째 지정). 리다이렉션 순서와 파이프는 빈칸 2-1 과 같은 원리입니다. nano 의 저장은 Write Out 의 O 라서 Ctrl+O 입니다. PuTTY 에서 Ctrl+C 는 복사가 아니라 실행 중인 프로그램에 SIGINT 를 보내는 키입니다.

4-1. 사용자 모드와 커널 모드

프로그램은 평소 사용자 모드에서 돈다. 파일·화면·네트워크·프로세스 생성처럼 하드웨어나 다른 프로세스에 영향을 주는 일은 직접 못 하고, 시스템 콜로 커널에 부탁해야 한다. 시스템 콜이 호출되면 CPU는 커널 모드로 전환되어 커널 코드를 실행한 뒤 결과를 들고 돌아온다.

[사용자 모드]  printf() ─▶ (glibc 버퍼) ─▶ write() 래퍼
                                              │ syscall 명령, 번호=1
───────────────────────────────────────────── ▼ ───────────
[커널 모드]                              sys_write() ─▶ 터미널 드라이버

  • man 3 printf → 섹션 3: C 라이브러리 함수

4-2. 예제 01 — printf와 write

src/01_write_vs_printf.c

/* 01_write_vs_printf.c — 라이브러리 함수(printf)와 시스템 콜(write) 비교
 * 빌드: make 01_write_vs_printf
 * 관찰: strace -e trace=write ./01_write_vs_printf
 *       strace -c ./01_write_vs_printf > /dev/null
 */
#include <stdio.h>
#include <string.h>
#include <unistd.h>

int main(void)
{
    const char *msg = "hello from write()\n";

    /* 1) 시스템 콜 write(): fd 1(stdout)로 바로 커널에 요청 */
    write(1, msg, strlen(msg));

    /* 2) 라이브러리 함수 printf(): 먼저 stdio 버퍼에 쌓았다가 write()로 내보냄 */
    for (int i = 0; i < 5; i++)
        printf("printf line %d\n", i);

    /* 3) 버퍼를 비우지 않고 끝나도 exit 과정에서 fflush가 호출됨 */
    return 0;
}

  • 파이프(| cat)나 파일로 보낼 때는 블록 단위 버퍼링 → printf 5줄이 write 한 번으로 합쳐지고, 먼저 호출한 write 문장보다 늦게 나온다.

/* 02_syscall_direct.c — glibc 래퍼 함수 vs syscall()로 직접 호출
 * 빌드: make 02_syscall_direct
 * 관찰: strace -e trace=getpid,write ./02_syscall_direct
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <unistd.h>
#include <sys/syscall.h>

int main(void)
{
    pid_t a = getpid();                 /* glibc 래퍼 */
    long  b = syscall(SYS_getpid);      /* 시스템 콜 번호로 직접 호출 */

    printf("getpid()            = %d\n", a);
    printf("syscall(SYS_getpid) = %ld\n", b);
    printf("SYS_getpid 번호     = %d\n", SYS_getpid);
    printf("SYS_write  번호     = %d\n", SYS_write);

    syscall(SYS_write, 1, "직접 write 호출\n", sizeof("직접 write 호출\n") - 1);
    return 0;
}

5-1. 시스템 콜은 실패한다

/* 03_errno.c — 시스템 콜 실패와 errno 확인
 * 빌드: make 03_errno
 * 실행: ./03_errno
 */
#include <stdio.h>
#include <string.h>
#include <errno.h>
#include <fcntl.h>
#include <unistd.h>

static void try_open(const char *path, int flags)
{
    int fd = open(path, flags);
    if (fd == -1) {
        /* 실패 시 -1 반환 + errno에 원인 번호가 저장됨 */
        printf("%-22s → 실패: errno=%d (%s)\n", path, errno, strerror(errno));
        return;
    }
    printf("%-22s → 성공: fd=%d\n", path, fd);
    close(fd);
}

int main(void)
{
    try_open("/etc/hostname", O_RDONLY);   /* 성공 */
    try_open("/no/such/file", O_RDONLY);   /* ENOENT */
    try_open("/etc/shadow", O_RDONLY);     /* EACCES (일반 사용자) */
    try_open("/etc", O_WRONLY);            /* EISDIR */

    errno = 0;
    if (close(100) == -1)
        perror("close(100)");              /* EBADF, perror는 메시지 앞에 접두어를 붙임 */
    return 0;
}

/etc                   → 실패: errno=21 (Is a directory)

src/04_proc_self.c

/* 04_proc_self.c — /proc/self/status에서 내 프로세스 정보 읽기
 * 빌드: make 04_proc_self
 * 실행: ./04_proc_self
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* key(예: "VmRSS")에 해당하는 줄의 값을 out에 복사. 성공 0, 실패 -1 */
static int read_status(const char *key, char *out, size_t size)
{
    FILE *fp = fopen("/proc/self/status", "r");
    if (fp == NULL) {
        perror("fopen");
        return -1;
    }

    char line[256];
    size_t klen = strlen(key);
    int found = -1;

    while (fgets(line, sizeof(line), fp) != NULL) {
        if (strncmp(line, key, klen) == 0 && line[klen] == ':') {
            char *v = line + klen + 1;
            while (*v == ' ' || *v == '\t')
                v++;
            v[strcspn(v, "\n")] = '\0';
            snprintf(out, size, "%s", v);
            found = 0;
            break;
        }
    }
    fclose(fp);
    return found;
}

int main(void)
{
    const char *keys[] = { "Name", "State", "Pid", "PPid", "Threads", "VmRSS" };
    char val[128];

    printf("--- malloc 전 ---\n");
    for (size_t i = 0; i < sizeof(keys) / sizeof(keys[0]); i++)
        if (read_status(keys[i], val, sizeof(val)) == 0)
            printf("%-8s %s\n", keys[i], val);

    /* 50MB를 할당하고 실제로 써야 RSS가 늘어난다 (Day 3 demand paging 예고) */
    size_t n = 50 * 1024 * 1024;
    char *buf = malloc(n);
    if (buf == NULL)
        return 1;
    memset(buf, 1, n);

    printf("--- 50MB 사용 후 ---\n");
    if (read_status("VmRSS", val, sizeof(val)) == 0)
        printf("%-8s %s\n", "VmRSS", val);

    free(buf);
    return 0;
}

6-1. fork — 하나가 둘이 된다

fork()는 호출한 프로세스를 복제한다. 한 번 호출해 두 번 반환한다.

반환값 누가 받나 의미

0 자식 "나는 자식이다"
> 0 부모 새로 태어난 자식의 PID

src/05_fork_basic.c

/* 05_fork_basic.c — fork() 반환값으로 부모/자식 구분
 * 빌드: make 05_fork_basic
 * 실행: ./05_fork_basic
 */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void)
{
    int x = 100;
    printf("[fork 전] PID=%d, x=%d\n", getpid(), x);
    fflush(stdout);   /* 버퍼를 비우지 않으면 자식에게 복사되어 두 번 출력될 수 있음 */

    pid_t pid = fork();
    if (pid == -1) {
        perror("fork");
        exit(1);
    }

    if (pid == 0) {
        /* 자식: fork() 반환값 0 */
        x += 1;
        printf("[자식] PID=%d, PPID=%d, x=%d\n", getpid(), getppid(), x);
        exit(0);
    }

    /* 부모: fork() 반환값 = 자식 PID */
    x -= 1;
    wait(NULL);
    printf("[부모] PID=%d, 자식 PID=%d, x=%d\n", getpid(), pid, x);
    return 0;
}

[fork 전] PID=177, x=100
[자식] PID=178, PPID=177, x=101
[부모] PID=177, 자식 PID=178, x=99

자식의 x가 101, 부모의 x가 99인 이유: fork 후 두 프로세스는 메모리를 따로 가진다. (실제로는 Copy-on-Write로 쓰는 순간에 복사된다 — Day 3에서 측정)

6-2. exec와 wait

  • exec: 현재 프로세스의 코드·데이터를 새 프로그램으로 통째로 교체한다. PID는 그대로다. 성공하면 돌아오지 않는다.
  • wait / waitpid: 부모가 자식의 종료를 기다리고 종료 상태를 받는다.
매크로 의미
WIFEXITED(s) exit()로 정상 종료했는가
WEXITSTATUS(s) 그때의 종료 코드(0~255)
WIFSIGNALED(s) 시그널로 죽었는가
WTERMSIG(s) 어떤 시그널이었나

src/06_fork_exec_wait.c

/* 06_fork_exec_wait.c — fork → exec → wait, 종료 상태 확인
 * 빌드: make 06_fork_exec_wait
 * 실행: ./06_fork_exec_wait            (기본: ls -l /tmp)
 *       ./06_fork_exec_wait ls /nope   (실패하는 명령 → 종료 코드 2)
 */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(int argc, char *argv[])
{
    char *def[] = { "ls", "-l", "/tmp", NULL };
    char **cmd = (argc > 1) ? &argv[1] : def;

    pid_t pid = fork();
    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        execvp(cmd[0], cmd);          /* 성공하면 이 아래는 실행되지 않음 */
        perror("execvp");
        _exit(127);                   /* exec 실패 관례: 127 */
    }

    int status;
    if (waitpid(pid, &status, 0) == -1) {
        perror("waitpid");
        return 1;
    }

    if (WIFEXITED(status))
        printf("[부모] 자식 %d 정상 종료, 종료 코드=%d\n", pid, WEXITSTATUS(status));
    else if (WIFSIGNALED(status))
        printf("[부모] 자식 %d 시그널로 종료, 시그널=%d\n", pid, WTERMSIG(status));
    return 0;
}

src/09_sigaction.c

/* 09_sigaction.c — SIGINT(Ctrl+C) 처리와 SIGCHLD로 자식 자동 수거
 * 빌드: make 09_sigaction
 * 실행: ./09_sigaction   → Ctrl+C를 두 번 눌러 보기 (세 번째에 종료)
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <signal.h>
#include <unistd.h>
#include <sys/wait.h>

static volatile sig_atomic_t g_int_count = 0;

static void on_sigint(int sig)
{
    (void)sig;
    g_int_count++;
    /* 핸들러 안에서는 async-signal-safe 함수만: printf 대신 write */
    const char msg[] = "\n[핸들러] SIGINT 받음\n";
    write(1, msg, sizeof(msg) - 1);
}

static void on_sigchld(int sig)
{
    (void)sig;
    /* 끝난 자식을 모두 수거 → 좀비가 남지 않음 */
    while (waitpid(-1, NULL, WNOHANG) > 0)
        ;
}

int main(void)
{
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sigemptyset(&sa.sa_mask);

    sa.sa_handler = on_sigint;
    sigaction(SIGINT, &sa, NULL);

    sa.sa_handler = on_sigchld;
    sa.sa_flags = SA_RESTART;          /* 시그널에 끊긴 sleep 외 시스템 콜 자동 재시작 */
    sigaction(SIGCHLD, &sa, NULL);

    /* 자식 하나를 만들어 2초 뒤 종료시킴 → SIGCHLD 핸들러가 수거 */
    if (fork() == 0) {
        sleep(2);
        _exit(0);
    }

    printf("PID=%d, Ctrl+C를 3번 누르면 종료합니다\n", getpid());
    while (g_int_count < 3)
        pause();                       /* 시그널이 올 때까지 잠듦 */

    printf("SIGINT 3회 → 종료\n");
    return 0;
}

핸들러 작성 규칙

  • 핸들러에서는 printf 대신 write 같은 async-signal-safe 함수만 쓴다.
  • 핸들러와 main이 함께 쓰는 변수는 volatile sig_atomic_t로 선언한다.
  • SIGCHLD 핸들러에서 waitpid(-1, NULL, WNOHANG)을 반복해야 동시에 끝난 자식까지 모두 수거한다.

8-1. 셸의 정체

우리가 매일 쓰는 bash도 결국 아래 루프다.

for (;;) {
    프롬프트 출력 → 한 줄 읽기 → 단어로 자르기
    내장 명령(cd, exit)이면 셸이 직접 처리
    아니면 fork → 자식은 execvp → 부모는 waitpid
    종료 코드 저장
}

왜 cd는 내장 명령이어야 하나? cd를 자식 프로세스에서 실행하면 자식의 현재 디렉터리만 바뀌고, 자식이 끝나면 사라진다. 셸 자신의 위치를 바꾸려면 셸 프로세스가 직접 chdir()을 호출해야 한다.

8-2. 전체 코드

src/myshell.c

/* myshell.c — Day 1 종합 실습: fork-exec-wait 루프로 만드는 미니 셸
 * 빌드: make myshell
 * 실행: ./myshell
 * 관찰: strace -f -e trace=clone,execve,wait4 ./myshell
 *
 * 지원: 일반 명령 실행, 내장 명령 exit / cd, 직전 종료 코드 표시
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>

#define MAX_LINE 1024
#define MAX_ARGS 64

/* line을 공백 기준으로 잘라 argv에 담고 인자 개수를 반환 */
static int parse(char *line, char *argv[])
{
    int argc = 0;
    char *tok = strtok(line, " \t\n");
    while (tok != NULL && argc < MAX_ARGS - 1) {
        argv[argc++] = tok;
        tok = strtok(NULL, " \t\n");
    }
    argv[argc] = NULL;                 /* execvp는 NULL로 끝나는 배열을 요구 */
    return argc;
}

int main(void)
{
    char line[MAX_LINE];
    char *argv[MAX_ARGS];
    int last = 0;                      /* 직전 명령의 종료 코드 */

    signal(SIGINT, SIG_IGN);           /* 셸 자신은 Ctrl+C로 죽지 않음 */

    for (;;) {
        printf("myshell[%d]$ ", last);
        fflush(stdout);

        if (fgets(line, sizeof(line), stdin) == NULL) {   /* Ctrl+D */
            printf("\n");
            break;
        }

        int argc = parse(line, argv);
        if (argc == 0)
            continue;

        /* 내장 명령: 자식이 아니라 셸 자신이 처리해야 하는 것 */
        if (strcmp(argv[0], "exit") == 0)
            break;
        if (strcmp(argv[0], "cd") == 0) {
            const char *dir = (argc > 1) ? argv[1] : getenv("HOME");
            if (chdir(dir) == -1) {
                perror("cd");
                last = 1;
            } else {
                last = 0;
            }
            continue;
        }

        pid_t pid = fork();
        if (pid == -1) {
            perror("fork");
            continue;
        }
        if (pid == 0) {
            signal(SIGINT, SIG_DFL);   /* 자식은 Ctrl+C에 정상 반응 */
            execvp(argv[0], argv);
            perror(argv[0]);
            _exit(127);
        }

        int status;
        waitpid(pid, &status, 0);
        if (WIFEXITED(status))
            last = WEXITSTATUS(status);
        else if (WIFSIGNALED(status))
            last = 128 + WTERMSIG(status);   /* bash와 같은 관례 */
    }
    return 0;
}
