1-3. 전원을 넣고 내 프로그램이 핀을 만지기까지

ESP32 는 전원이 들어오면 곧바로 setup() 이 돈다. Pi 는 아래 단계를 모두 지나야 사용자 프로그램이 핀에 접근할 수 있다.

[ESP32]  전원 ─▶ ROM 부트로더 ─▶ 내 펌웨어 setup()/loop()   (레지스터 직접)

[Pi 4]   전원 ─▶ EEPROM 부트로더 ─▶ start4.elf (GPU 펌웨어)
              ─▶ config.txt 읽기 · Device Tree(.dtb) + overlay 적용
              ─▶ Linux 커널 ─▶ 드라이버 probe (gpio, i2c, spi, pwm, uart)
              ─▶ /dev/gpiochip0, /dev/i2c-1 ... 장치 파일 생성
              ─▶ systemd ─▶ sshd ─▶ 로그인 ─▶ ./내프로그램   (장치 파일로 요청)

5교시에 고치는 config.txt 가 이 흐름의 중간에서 "어떤 하드웨어를 켤지"를 정한다. 그래서 config.txt 를 바꾸면 재부팅해야 반영된다. 7교시에 dmesg 로 드라이버가 장치를 잡는 장면을 직접 확인한다.

2-3. 대체 기능 — 한 핀, 여러 역할

GPIO 핀은 평범한 입출력 말고도 대체 기능(ALT) 을 가진다. 예를 들어 GPIO18 은 일반 입출력도 되고 PWM0 출력도 된다. 어떤 기능으로 쓸지는 SoC 의 GPFSEL 레지스터가 정하는데, Linux 에서는 이것을 우리가 직접 쓰지 않고 Device Tree 와 드라이버가 정한다 (5교시).

2-4. ⚠ 전기적 주의 — MCU 과목보다 엄격하다

  • GPIO 는 3.3V 전용이다. 5V 를 GPIO 에 넣으면 SoC 가 망가지고, ESP32 와 달리 보드 교체 외에 방법이 없다.
  • 핀 하나에서 꺼낼 전류는 16mA 이하로 잡는다. LED 에는 반드시 220Ω 을 직렬로 넣는다.
  • 5V 핀과 3V3 핀, 5V 와 GND 를 절대 맞닿게 하지 않는다. 배선을 바꿀 때는 가능하면 sudo poweroff 후 전원을 뺀다.
  • 5V 를 내보내는 센서(HC-SR04 Echo 등)는 분압 회로를 거쳐서만 연결한다 (Day 3).
  • 브레드보드 위에 금속 물건(드라이버, 클립)을 올려 두지 않는다.

2-5. Extension Board 연결

  1. 40-Pin 케이블의 빨간 줄을 Pi 헤더 1번 핀(3V3) 쪽에 맞춰 꽂는다.
  2. 케이블 반대쪽을 Extension Board 에 꽂는다 (홈 방향이 맞아야 들어간다).
  3. Extension Board 를 브레드보드 가운데 홈에 걸쳐 꽂는다. 양쪽 핀이 서로 다른 열에 들어가야 단락이 없다.
  4. Extension Board 의 GND 를 브레드보드 아래쪽 파란 레일(−)에 점퍼선으로 잇는다.

거꾸로 꽂으면 Extension Board 의 이름표가 모두 틀어져 3V3 라고 적힌 곳에 5V 가 나온다. 전원을 넣기 전에 짝과 서로 확인한다.

3-1. 모니터 · 키보드 없이 접속하는 두 단계

강의실 Pi 에는 모니터 · 키보드가 없다. 그래서 처음에는 USB-C 케이블 하나로 PC 와 Pi 를 직접 잇고(USB gadget mode), 그 연결로 들어가 Wi-Fi 를 설정한 뒤 Wi-Fi 접속으로 갈아탄다.

[1단계 · 3~4교시]   PC ══ USB-C 데이터 케이블 ══ Pi
                    전원 + 네트워크를 한 줄로. PC 와 Pi 둘만의 작은 망 (Pi = 10.12.194.1)

[2단계 · 4교시 끝~] PC ── 강의장 Wi-Fi ── Pi
                    전원은 5V 3A 어댑터. Day 3 모터 실습까지 이 상태로 진행

USB gadget mode 는 Pi 가 PC 에게 "나는 USB 랜카드입니다" 라고 자신을 소개하는 기능이다. 휴대폰의 USB 테더링과 같은 원리이고, Pi 4 는 전원을 꽂던 USB-C 포트가 이 역할을 한다. Raspberry Pi OS Trixie 의 2025-10-20 이후 이미지에는 이 기능(rpi-usb-gadget 패키지)이 기본으로 들어 있다.

3-4. 첫 부팅 전에 — user-data 에 gadget mode 켜기

3-5. PC 준비 — 드라이버 · PuTTY · FileZilla

  • Windows 에는 이 USB 랜카드용 기본 드라이버가 없다. github.com/raspberrypi/rpi-usb-gadget/releases 에서 rpi-usb-gadget-driver-setup.exe 를 받아 실행한다 (PC 당 한 번). 강의장 PC 에 강사가 미리 설치해 두면 이 단계는 건너뛴다.
  • PuTTY · FileZilla 는 Linux & Shell 과목에서 설치한 것을 그대로 쓴다.

3-6. 첫 부팅 — PC 의 USB 포트로 전원 넣기

  1. microSD 를 Pi 아래쪽 슬롯에 끝까지 꽂는다.

  3. 허브 · 모니터 USB 포트를 거치지 말고 PC 본체 포트(데스크톱은 뒷면)에 직접 꽂는다.
  4. 첫 부팅은 파일시스템 확장 · 설정 적용 후 스스로 한 번 재부팅한다. 2~3분 기다린다.

4-2. PuTTY 로 USB 접속

Host Name 에 rpi-07.local, Port 22, 연결 종류 SSH 를 넣고 Saved Sessions 에 rpi-07-usb 로 저장한 뒤 Open 한다. 처음 접속하면 호스트 키 경고가 뜨는데 Accept 를 누른다.

이름으로 안 되면 Host Name 에 10.12.194.1 을 넣는다. PC 의 인터넷 공유를 켜지 않았을 때 USB 쪽 Pi 가 쓰는 고정 주소다.

pi@rpi-07:~ $

이 프롬프트가 보이면 성공이다. Linux & Shell 의 VM 은 포트 포워딩 때문에 127.0.0.1:2222 로 접속했지만, Pi 는 USB 랜카드 너머에 있는 진짜 컴퓨터라 기본 포트 22 로 바로 접속한다.

4-3. 40명이 같은 이름 · 같은 IP 를 써도 되나?

연결 망의 범위 이름 · IP 가 같으면
USB gadget PC 1대 ↔ Pi 1대, 케이블 안에서만 문제없다. 40대 모두 10.12.194.1 이어도 서로 보이지 않는다
강의장 Wi-Fi 40대 전부 한 망 충돌한다. 먼저 켜진 보드가 rpi-07.local 을 갖고, 나중 보드는 자동으로 rpi-07-2.local 이 된다 → 남의 보드에 접속

그래서 호스트 이름은 처음부터 좌석 번호로 짓는다. 이름이 틀렸다면 Wi-Fi 에 붙기 전에(지금) 바꾼다.

sudo raspi-config nonint do_hostname rpi-07   # 다르면 고치기 (/etc/hostname · /etc/hosts 함께 변경)
sudo reboot                                   # 1분 뒤 PuTTY 다시 접속

5-4. 왜 disable-bt 인가 — PL011 과 mini UART

UART 클럭 기본 연결 특징
PL011 (ttyAMA0) 독립 클럭 Bluetooth 보율이 정확함
mini UART (ttyS0) CPU 코어 클럭에 묶임 GPIO14 · 15 클럭이 바뀌면 보율이 흔들림

Pi 4 는 기본으로 좋은 UART 를 블루투스에 주고, 핀에는 mini UART 를 연결한다. 수업에서는 블루투스를 쓰지 않으므로 disable-bt 로 PL011 을 GPIO 로 돌려받는다. /dev/serial0 은 "지금 GPIO 에 연결된 UART"를 가리키는 별명이다.

6-5. 예제 01 — 보드 정보를 파일로 읽기

첫 C 프로그램은 Pi 위에서 gcc 가 동작하는지 확인하면서, Linux 에서는 보드 정보도 파일로 읽는다는 것을 보여 준다.

src/01_board_info.c

/* 01_board_info.c — 보드 정보를 "파일"로 읽기 (/proc, /sys, uname)
 * 빌드: make 01_board_info
 * 실행: ./01_board_info
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/utsname.h>
#include <unistd.h>

/* 파일의 첫 줄을 buf 에 읽고 끝의 '\n' 을 지운다. 실패하면 -1 */
static int read_line(const char *path, char *buf, size_t n)
{
    FILE *fp = fopen(path, "r");
    if (fp == NULL)
        return -1;
    if (fgets(buf, (int)n, fp) == NULL) {
        fclose(fp);
        return -1;
    }
    fclose(fp);
    buf[strcspn(buf, "\n")] = '\0';
    return 0;
}

int main(void)
{
    char buf[128];
    struct utsname u;

    /* 1) Device Tree 가 알려 주는 보드 모델 */
    if (read_line("/proc/device-tree/model", buf, sizeof buf) == 0)
        printf("모델      : %s\n", buf);
    else
        printf("모델      : (읽기 실패 — Raspberry Pi 가 아님?)\n");

    /* 2) 커널 정보 — 시스템 콜 uname() */
    if (uname(&u) == 0)
        printf("커널      : %s %s (%s)\n", u.sysname, u.release, u.machine);

    /* 3) 온라인 CPU 코어 수 */
    printf("CPU 코어  : %ld\n", sysconf(_SC_NPROCESSORS_ONLN));

    /* 4) SoC 온도 — thermal 드라이버가 밀리도(m°C) 정수로 보여 준다 */
    if (read_line("/sys/class/thermal/thermal_zone0/temp", buf, sizeof buf) == 0)
        printf("SoC 온도  : %.1f °C\n", atoi(buf) / 1000.0);

    /* 5) GPIO 칩 장치 파일을 내 권한으로 열 수 있는가 */
    if (access("/dev/gpiochip0", F_OK) != 0)
        printf("GPIO 칩   : /dev/gpiochip0 없음\n");
    else if (access("/dev/gpiochip0", R_OK | W_OK) == 0)
        printf("GPIO 칩   : /dev/gpiochip0 읽기·쓰기 가능\n");
    else
        printf("GPIO 칩   : /dev/gpiochip0 권한 없음 (gpio 그룹 확인)\n");

    return 0;
}

🎬 D1-8 pull-up 버튼과 엣지 — 버튼을 누르고 뗄 때 전압 · 값 · 엣지 · 바운싱이 어떻게 보이는지

8-1. 배선 — GPIO5 에 버튼 추가

LED 는 그대로 두고, 버튼 한쪽을 GPIO5 (물리 29번), 다른 쪽을 GND 레일에 꽂는다. 외부 저항은 넣지 않는다 — Pi 내부의 pull-up 저항을 켜서 쓴다 (MCU 의 INPUT_PULLUP 과 같다).

버튼 상태 핀 전압 (pull-up) 읽은 값
안 누름 내부 저항이 3.3V 로 끌어올림 1 (active)
누름 GND 와 연결 0 (inactive)

누르면 0 이 되는 것이 처음에는 어색하다. 그래서 누르는 순간 = 1 → 0 으로 떨어지는 엣지(falling) 다.

8-2. 예제 — gpioget 과 gpiomon

gpioget -c gpiochip0 -b pull-up 5                 # 안 누르고 실행 → "5"=active
gpioget -c gpiochip0 -b pull-up 5                 # 누른 채 실행   → "5"=inactive
gpioget -c gpiochip0 -b pull-up --numeric 5       # 숫자로만 → 1 / 0
gpioget -c gpiochip0 5                            # bias 없이 → 값이 들쭉날쭉 (떠 있는 핀)

마지막 줄처럼 bias 를 주지 않으면 버튼을 누르지 않았을 때 핀이 어디에도 연결되지 않아(floating) 값이 0 과 1 을 오간다. 입력 핀은 항상 pull-up 또는 pull-down 이 필요하다.

gpiomon -c gpiochip0 -b pull-up -e falling 5             # 누를 때마다 한 줄 (Ctrl+C 로 종료)
gpiomon -c gpiochip0 -b pull-up -e both -p 10ms 5        # 누름 · 뗌 모두, 10ms 디바운스
gpiomon -c gpiochip0 -b pull-up -e falling -n 3 5        # 3번 받고 끝

1260.412335071	falling	"5"
1261.087120554	falling	"5"
1261.093004713	falling	"5"     ← 한 번 눌렀는데 두 줄: 바운싱

맨 앞 숫자는 커널이 엣지를 받은 시각(초.나노초) 이다. 한 번 눌렀는데 몇 ms 차이로 여러 줄이 찍히면 접점이 떨리는 바운싱이다. -p 10ms 를 주면 커널이 10ms 안의 떨림을 걸러 준다. 출력 형식은 버전에 따라 조금 다를 수 있다.

#!/bin/bash
# check_env.sh — Embedded I/O 제어 Day 1 실습 환경 점검
# 대상: Raspberry Pi 4 + Raspberry Pi OS Lite 64-bit (Trixie)
# 사용법: bash check_env.sh

PASS=0; FAILN=0
ok()   { printf "  [ OK ] %s\n" "$*"; PASS=$((PASS + 1)); }
warn() { printf "  [WARN] %s\n" "$*"; }
fail() { printf "  [FAIL] %s\n" "$*"; FAILN=$((FAILN + 1)); }

echo "== 1. 보드와 OS =="
MODEL=$( (tr -d '\0' < /proc/device-tree/model) 2>/dev/null )
if [[ "$MODEL" == "Raspberry Pi 4"* ]]; then ok "보드   : $MODEL"
else fail "보드   : ${MODEL:-알 수 없음} (Raspberry Pi 4 가 아님)"; fi
. /etc/os-release
if [[ "$VERSION_CODENAME" == "trixie" ]]; then ok "OS     : $PRETTY_NAME"
else fail "OS     : $PRETTY_NAME (수업 기준은 trixie — libgpiod v2)"; fi
if [[ "$(uname -m)" == "aarch64" ]]; then ok "커널   : $(uname -r) (aarch64)"
else warn "커널   : $(uname -r) ($(uname -m)) — 64-bit 이미지 권장"; fi

echo "== 2. 전원과 온도 =="

✏️ 빈칸 채우기 8-1

버튼 입력 명령의 빈칸을 채우세요.

gpioget -c gpiochip0 -b  5            # 내부 pull-up 켜고 GPIO5 읽기
gpiomon -c gpiochip0 -b pull-up -e  5  # 누르는 순간(1→0)만 보기
gpiomon -c gpiochip0 -b pull-up -e both  10ms 5   # 10ms 디바운스
gpiomon -c gpiochip0 -b pull-up -e falling  3 5   # 3번 받고 끝
🔒 정답 보기 8-1 
gpioget -c gpiochip0 -b pull-up 5            # 내부 pull-up 켜고 GPIO5 읽기
gpiomon -c gpiochip0 -b pull-up -e falling 5  # 누르는 순간(1→0)만 보기
gpiomon -c gpiochip0 -b pull-up -e both -p 10ms 5   # 10ms 디바운스
gpiomon -c gpiochip0 -b pull-up -e falling -n 3 5   # 3번 받고 끝

-b(bias) 로 내부 저항을 고릅니다. pull-up 회로에서 버튼을 누르면 1 → 0 으로 떨어지므로 falling 엣지가 "누름"입니다. -p(debounce period) 는 커널이 접점 떨림을 걸러 줄 시간, -n 은 받을 이벤트 수입니다.

✏️ 괄호 넣기 8-3

  1. pull-up 회로에서 버튼을 누르지 않았을 때 읽은 값은 이다.
  2. bias 를 주지 않은 입력 핀은 값이 들쭉날쭉하다. 이런 상태를 라 한다.
  3. 한 번 눌렀는데 이벤트가 여러 번 찍히는 현상을 이라 한다.
  4. gpiomon 이 출력하는 맨 앞 숫자는 이 엣지를 받은 시각이다.
🔒 정답 보기 8-3
  1. 1
  2. floating
  3. 바운싱
  4. 커널

pull-up 은 평소 핀을 3.3V(1)로 끌어올리고, 버튼이 GND 로 당길 때만 0 이 됩니다. 아무 데도 연결되지 않은 핀은 주변 잡음에 따라 값이 바뀌는 floating 상태입니다. 기계식 접점은 수 ms 동안 떨려 바운싱이 생깁니다. 타임스탬프는 커널이 인터럽트를 받은 순간 찍으므로, Day 2 반응속도 게임에서 이 값의 차이로 ms 를 잽니다(🎬 D1-8).
